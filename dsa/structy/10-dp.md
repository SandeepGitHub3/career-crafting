# Foundations

## 1. Fib

**Problem**
- Return the n-th Fibonacci number, solved recursively.
- `fib(0) = 0`, `fib(1) = 1`, otherwise sum of the previous two.

**Skeleton**
- **State:** `n`
- **Meaning:** the n-th Fibonacci number
- **Base:** `n < 2 → n`
- **Combine:** `fib(n-1) + fib(n-2)`

> **Why memo matters here:** the naive tree is `O(2^n)` because `fib(n-2)` is recomputed on both branches. Memo collapses it to `O(n)` — this is the canonical demo of *overlapping subproblems*.

<img width="520" alt="fib recursion tree" src="https://github.com/user-attachments/assets/8f3baa9d-3992-452d-a5f0-97c4073f5b5d" />
<img width="520" alt="fib repeated subproblems" src="https://github.com/user-attachments/assets/83c96f2c-21f9-493e-ba61-392a89783e77" />
<img width="520" alt="fib memo structure" src="https://github.com/user-attachments/assets/c228e271-8976-44db-83ee-469636e13af4" />
<img width="520" alt="fib memo walkthrough" src="https://github.com/user-attachments/assets/392c85c5-6f0c-430f-911e-689d9898807b" />
<img width="520" alt="fib complexity" src="https://github.com/user-attachments/assets/400be2f7-cbc0-4071-8e2e-67dfe335634e" />

```java
public static int fib(int n) {
    return fib(n, new HashMap<>());
}

private static int fib(int n, Map<Integer, Integer> memo) {
    if (n < 2) return n;
    if (memo.containsKey(n)) return memo.get(n);

    int fibRes = fib(n - 1, memo) + fib(n - 2, memo);
    memo.put(n, fibRes);
    return fibRes;
}
```

**Complexity:** `O(n)` time, `O(n)` space.

# Numeric target problems

> All four share one state: **the remaining amount**. What changes is the verb.

## 2. Sum Possible

**Problem**
- Given a non-negative `amount` and a list of positive numbers.
- Return `true` if the amount can be formed by summing numbers from the list.
- Numbers may be reused without limit.

**Skeleton**
- **State:** remaining `amount`
- **Meaning:** is this amount reachable?
- **Base:** `amount == 0 → true`; `amount < 0 → false`
- **Combine:** `OR` — short-circuit on the first `true`

<img width="520" alt="sumPossible recursion tree" src="https://github.com/user-attachments/assets/ff76a5ea-b3bd-47ad-a03a-1e7a890632fd" />
<img width="520" alt="sumPossible subtree overlap" src="https://github.com/user-attachments/assets/d5898597-e06c-4080-bc1b-0755d5eb8edf" />
<img width="520" alt="sumPossible complexity" src="https://github.com/user-attachments/assets/ec012cbd-9d8b-41fa-9d00-2ede17d5b9e5" />

```java
public static boolean sumPossible(int amount, List<Integer> numbers) {
    return sumPossible(amount, numbers, new HashMap<>());
}

private static boolean sumPossible(int amount, List<Integer> numbers,
                                  Map<Integer, Boolean> memo) {
    if (amount < 0) return false;
    if (amount == 0) return true;
    if (memo.containsKey(amount)) return memo.get(amount);

    boolean res = false;
    for (int num : numbers) {
        if (sumPossible(amount - num, numbers, memo)) {
            res = true;
            break;
        }
    }

    memo.put(amount, res);
    return res;
}
```

> **Style fix applied.** The original wrote `res = sumPossible(...)` directly inside the loop. That is only correct because of the `break` immediately after — remove the `break` and a later `false` silently erases an earlier `true`. Accumulating with `if (...) { res = true; break; }` makes the correctness local instead of depending on a statement three lines down. Interviewers notice this.

**Complexity:** `O(amount × n)` time, `O(amount)` space.

## 3. Min Change

**Problem**
- Given an `amount` and an array of coins, unlimited reuse.
- Return the **minimum number of coins** summing to the amount.
- Return `-1` if impossible.

**Skeleton**
- **State:** remaining `amount`
- **Meaning:** fewest coins to make this amount
- **Base:** `amount == 0 → 0`; `amount < 0 → -1`
- **Combine:** `MIN(1 + sub)` over all coins, **skipping** any `sub < 0`

<img width="520" alt="minChange recursion tree" src="https://github.com/user-attachments/assets/4bca82d7-2dec-4ac9-9011-0b4a261f9e10" />
<img width="280" alt="minChange complexity" src="https://github.com/user-attachments/assets/d62df123-0615-4992-a049-948995a5a024" />
<img width="520" alt="minChange memo walkthrough" src="https://github.com/user-attachments/assets/f6e9b3ff-d9cd-421b-959d-39a31c2975f2" />

```java
public static int minChange(int amount, List<Integer> coins) {
    return minChange(amount, coins, new HashMap<>());
}

private static int minChange(int amount, List<Integer> coins,
                             Map<Integer, Integer> memo) {
    if (amount < 0) return -1;
    if (amount == 0) return 0;
    if (memo.containsKey(amount)) return memo.get(amount);

    int minCoins = Integer.MAX_VALUE;
    for (int coin : coins) {
        int currCoins = minChange(amount - coin, coins, memo);
        if (currCoins >= 0) {                          // guard: skip impossible
            minCoins = Math.min(1 + currCoins, minCoins);
        }
    }

    minCoins = (minCoins == Integer.MAX_VALUE) ? -1 : minCoins;
    memo.put(amount, minCoins);
    return minCoins;
}
```

> **Sentinel discipline — the one thing to remember.** `-1` must never enter a `MIN` comparison, because `-1` wins every `Math.min` and poisons everything downstream. Two valid styles, and you must pick exactly one:
>
> - **Explicit guard** (used above): store `-1` in the table, check `>= 0` before consuming a sub-answer.
> - **Big sentinel:** store `amount + 1` for unreachable, no guard needed, convert to `-1` only at the boundary.
>
> Mixing them — storing `-1` *and* skipping the guard — is the single most common bug in this problem.
>
> Also note `1 + currCoins` and never `1 + minCoins`. Adding to `Integer.MAX_VALUE` wraps negative and silently corrupts the table.

**Complexity:** `O(amount × coins)` time, `O(amount)` space.

## 4. Counting Change

> ⚠️ **The tricky one.** This is the only problem here where getting the *state* wrong still produces a plausible-looking number.

**Problem**
- Given an `amount` and coins, unlimited reuse.
- Return the number of **distinct combinations** making the amount.
- `countingChange(4, [1,2,3]) → 4`: `1+1+1+1`, `1+1+2`, `1+3`, `2+2`

**Why this one is different**
- Order must **not** matter. `1+3` and `3+1` are the same combination.
- If you loop over all coins from a single `amount` state (like `minChange`), you count **permutations** and overshoot.
- Fix: add a **coin index** to the state and never look backwards. At each level you decide *how many of coin `c`* to use, then move permanently to `c+1`.

**Skeleton**
- **State:** `(amount, coinIndex)` — two-dimensional, memo key `"amount--c"`
- **Meaning:** number of ways to make `amount` using only coins from index `c` onward
- **Base:** `amount == 0 → 1`; `c >= coins.size() → 0`
- **Combine:** `SUM` over quantities `qty = 0, 1, 2, …` while `qty * coin <= amount`

<img width="520" alt="countingChange permutation problem" src="https://github.com/user-attachments/assets/f824989d-050a-4f15-92ee-870489aae0fc" />
<img width="520" alt="countingChange two-dimensional state" src="https://github.com/user-attachments/assets/924ff37c-3556-4621-ba3f-fad0b981a94f" />
<img width="340" alt="countingChange complexity" src="https://github.com/user-attachments/assets/be3b32ee-a8e7-45ea-9c85-364ad143e0d9" />

```java
public static int countingChange(int amount, List<Integer> coins) {
    return countingChange(amount, coins, 0, new HashMap<>());
}

private static int countingChange(int amount, List<Integer> coins, int c,
                                  Map<String, Integer> memo) {
    if (amount == 0) return 1;                  // exactly one way: take nothing more
    if (c >= coins.size()) return 0;            // ran out of coin types

    String key = amount + "--" + c;
    if (memo.containsKey(key)) return memo.get(key);

    int totalWays = 0;
    int coin = coins.get(c);
    for (int qty = 0; qty * coin <= amount; qty++) {
        totalWays += countingChange(amount - qty * coin, coins, c + 1, memo);
    }

    memo.put(key, totalWays);
    return totalWays;
}
```

> ### 🐞 Bug fixed from the original
>
> The original base case was:
> ```java
> if (amount < 0 || c >= coins.size() || amount < coins.get(c)) return -1;
> ```
> The third clause is wrong. `amount < coins.get(c)` means *"the current coin is too big"* — but that is not a dead end, because **later coins may still be small enough**. Returning `-1` there abandons the rest of the coin list.
>
> **Counter-example:** `countingChange(1, [2, 1])`. At `c = 0`, `amount(1) < coins[0](2)` → returns `-1`. Correct answer is `1` (a single 1-coin). The `qty = 0` branch already handles "skip this coin" correctly, so the clause is not only wrong, it is redundant.
>
> Two smaller cleanups: this is a **counting** problem, so the not-found value is `0`, not `-1` — which removes the need for the `if (curr >= 0)` filter entirely. And `coins.get(c)` is now hoisted out of the loop.

**Complexity:** `O(amount × coins)` states, `O(amount / coin)` work each.

## 5. Summing Squares

**Problem**
- Given a target `n`, return the **minimum count of perfect squares** summing to it.
- Perfect squares are `i*i` for `i >= 1`: `1, 4, 9, 16, …` (`8` is not one).

**Skeleton**
- **State:** remaining `n`
- **Meaning:** fewest perfect squares summing to `n`
- **Base:** `n == 0 → 0`; `n < 0 → -1`
- **Combine:** `MIN(1 + sub)` over `i*i` for `i = 1 … √n`

<img width="620" alt="summingSquares recursion and walkthrough" src="https://github.com/user-attachments/assets/9c4ccb1c-5392-48bf-b919-a6a4cf7d4b0e" />

```java
public static int summingSquares(int n) {
    return summingSquares(n, new HashMap<>());
}

private static int summingSquares(int n, Map<Integer, Integer> memo) {
    if (n == 0) return 0;
    if (n < 0) return -1;
    if (memo.containsKey(n)) return memo.get(n);

    int minSumSquare = Integer.MAX_VALUE;
    for (int i = 1; i * i <= n; i++) {
        int curr = summingSquares(n - i * i, memo);
        if (curr >= 0) {
            minSumSquare = Math.min(minSumSquare, 1 + curr);
        }
    }

    minSumSquare = (minSumSquare == Integer.MAX_VALUE) ? -1 : minSumSquare;
    memo.put(n, minSumSquare);
    return minSumSquare;
}
```

> **Two fragilities repaired.**
>
> 1. The original never converted `Integer.MAX_VALUE` back to `-1` before memoizing. It happens to work — because `1` is always an available square, every `n >= 1` is reachable — but the code is one input-constraint change away from returning `2147483647`. Convert at the boundary anyway; it's free and it makes the invariant explicit.
> 2. `i <= Math.sqrt(n)` calls a floating-point `sqrt` on **every iteration**, and floating-point rounding at exact squares is a known source of off-by-one. `i * i <= n` is integer-only and faster.

**Complexity:** `O(n × √n)` time, `O(n)` space.

# Grid problems

> State is always `(row, col)`. Memo key is a composite string `"r--c"` — see the [bug checklist](#appendix-b-bug-checklist) on why `r + c` is not a valid key.

## 6. Count Paths

**Problem**
- Grid of `"O"` (open) and `"X"` (wall).
- Move **down or right only**, cannot pass through walls.
- Return the number of paths from top-left to bottom-right.
- `[["O","O"],["O","O"]] → 2`

**Skeleton**
- **State:** `(r, c)`
- **Meaning:** number of paths from `(r, c)` to the bottom-right corner
- **Base:** out of bounds → `0`; wall → `0`; **bottom-right cell → `1`**
- **Combine:** `SUM` of down + right

<img width="520" alt="countPaths grid recursion" src="https://github.com/user-attachments/assets/acfa8941-1d35-4f93-9a4e-c34bca909c4a" />
<img width="280" alt="countPaths base cases" src="https://github.com/user-attachments/assets/79cb6b44-8c0e-4b02-a03a-d3793a28469d" />
<img width="520" alt="countPaths memo table" src="https://github.com/user-attachments/assets/4cd91af9-53e5-4b3d-8f6f-e17be6711d10" />
<img width="290" alt="countPaths complexity" src="https://github.com/user-attachments/assets/1e188a0d-45b6-4aaa-bce7-e1601b3f7a70" />

```java
public static int countPaths(List<List<String>> grid) {
    return countPaths(0, 0, grid, new HashMap<>());
}

private static int countPaths(int r, int c, List<List<String>> grid,
                              Map<String, Integer> memo) {
    int rows = grid.size(), cols = grid.get(0).size();

    if (r >= rows || c >= cols) return 0;                    // fell off the grid
    if (grid.get(r).get(c).equals("X")) return 0;            // wall
    if (r == rows - 1 && c == cols - 1) return 1;            // arrived

    String key = r + "--" + c;
    if (memo.containsKey(key)) return memo.get(key);

    int paths = countPaths(r + 1, c, grid, memo)
              + countPaths(r, c + 1, grid, memo);

    memo.put(key, paths);
    return paths;
}
```

> ### 🐞 Two bugs fixed from the original
>
> **1. Unreachable destination base case.** The original wrote:
> ```java
> if (r == grid.size() && c == grid.get(0).size()) return 1;
> ```
> The bottom-right cell is at index `(rows-1, cols-1)`, not `(rows, cols)`. And even if you wanted `(rows, cols)`, the bounds check on the line above already returned `0` for it. So this line **never fired** and the method returned `0` for every input. Classic inclusive-range slip: `size()` is one past the last valid index.
>
> **2. `==` on Strings.** `grid.get(r).get(c) == "X"` compares **references**, not characters. It appears to work when strings come from literals in the same class (the constant pool interns them), then silently returns `false` the moment the grid is built from input, a file, or `new String("X")`. Always `.equals()`.
>
> Minor: `rows`/`cols` hoisted so the same values aren't recomputed four times per call.

**Complexity:** `O(rows × cols)` time and space.

## 7. Max Path Sum

**Problem**
- Grid of non-negative numbers.
- Move **down or right only**.
- Return the **maximum sum** along a path from top-left to bottom-right.
- `[[1,3,12],[5,1,1],[3,6,1]] → 18`

**Skeleton**
- **State:** `(r, c)`
- **Meaning:** best sum achievable from `(r, c)` to the bottom-right corner
- **Base:** out of bounds → `Integer.MIN_VALUE`; bottom-right → that cell's value
- **Combine:** `cell + MAX(down, right)`

<img width="520" alt="maxPathSum grid recursion" src="https://github.com/user-attachments/assets/c4b66d7a-7450-43f5-99a1-8285b01593ad" />
<img width="280" alt="maxPathSum base cases" src="https://github.com/user-attachments/assets/aa644646-13b0-4631-84f3-8f47a0c970de" />
<img width="290" alt="maxPathSum complexity" src="https://github.com/user-attachments/assets/4c6b7ff9-887e-461e-8a85-e513feb3253f" />

```java
public static int maxPathSum(List<List<Integer>> grid) {
    return maxPathSum(0, 0, grid, new HashMap<>());
}

private static int maxPathSum(int r, int c, List<List<Integer>> grid,
                              Map<String, Integer> memo) {
    int rows = grid.size(), cols = grid.get(0).size();

    if (r >= rows || c >= cols) return Integer.MIN_VALUE;    // invalid path
    if (r == rows - 1 && c == cols - 1) return grid.get(r).get(c);

    String key = r + "--" + c;
    if (memo.containsKey(key)) return memo.get(key);

    int best = grid.get(r).get(c) + Math.max(
        maxPathSum(r + 1, c, grid, memo),
        maxPathSum(r, c + 1, grid, memo)
    );

    memo.put(key, best);
    return best;
}
```

> **Why `MIN_VALUE` and not `0` for out of bounds.** With `0`, walking off the edge would look like a legal path worth nothing, and the `MAX` might prefer it over a real path — you'd get answers for paths that don't exist. `MIN_VALUE` guarantees the invalid branch always loses.
>
> **Why this doesn't overflow.** `MIN_VALUE + cellValue` would wrap, but it never happens: the destination cell returns early, so any cell that recurses has at least one in-bounds neighbour, and `Math.max` picks it. Worth being able to say out loud — an interviewer may well ask.
>
> *(This solution was missing from the original notes.)*

**Complexity:** `O(rows × cols)` time and space.

# Array / index problems

## 8. Non-Adjacent Sum

**Problem**
- List of non-negative numbers.
- Return the **maximum sum of non-adjacent elements**; no limit on how many you take.
- `[2, 4, 5, 12, 7] → 16` (`4 + 12`)

**Skeleton**
- **State:** `index`
- **Meaning:** best sum obtainable from `index` onward
- **Base:** `index >= size → 0`
- **Combine:** `MAX(take: nums[i] + f(i+2), skip: f(i+1))`

> **The mental model:** at each element you have exactly two choices. *Take* it and you must jump two (skipping the neighbour). *Skip* it and you move one. That `+2` versus `+1` **is** the adjacency constraint — there is no separate check.

<img width="520" alt="nonAdjacentSum decision tree" src="https://github.com/user-attachments/assets/36c18463-fa1a-4707-b869-e46ee0c76adb" />
<img width="520" alt="nonAdjacentSum complexity" src="https://github.com/user-attachments/assets/8203ab9b-6db9-44d0-9df1-b4471fc1c397" />

```java
public static int nonAdjacentSum(List<Integer> nums) {
    return nonAdjacentSum(0, nums, new HashMap<>());
}

private static int nonAdjacentSum(int index, List<Integer> nums,
                                  Map<Integer, Integer> memo) {
    if (index >= nums.size()) return 0;
    if (memo.containsKey(index)) return memo.get(index);

    int sum = Math.max(
        nums.get(index) + nonAdjacentSum(index + 2, nums, memo),   // take
        nonAdjacentSum(index + 1, nums, memo)                      // skip
    );

    memo.put(index, sum);
    return sum;
}
```

**Complexity:** `O(n)` time, `O(n)` space. *(Bottom-up brings space to `O(1)` — you only ever need the last two values.)*

## 9. Array Stepper

**Problem**
- Start at index `0`. At index `i` you may move forward `1 … nums[i]` steps.
- Return whether the **last index** is reachable.
- `[2, 4, 2, 0, 0, 1] → true` (0 → 1 → 5)

**Skeleton**
- **State:** `index`
- **Meaning:** is the last index reachable from here?
- **Base:** `index == size - 1 → true`; `index > size - 1 → false`
- **Combine:** `OR` over steps `1 … nums[index]`, short-circuit on first `true`

<img width="520" alt="arrayStepper recursion" src="https://github.com/user-attachments/assets/be373ba7-2925-4552-bdfe-36997f0866eb" />
<img width="280" alt="arrayStepper complexity" src="https://github.com/user-attachments/assets/e2adfdcf-c273-4565-a8e4-3ef3d5b303a4" />

```java
public static boolean arrayStepper(List<Integer> nums) {
    return arrayStepper(0, nums, new HashMap<>());
}

private static boolean arrayStepper(int index, List<Integer> nums,
                                    Map<Integer, Boolean> memo) {
    if (index >= nums.size() - 1) return index == nums.size() - 1;
    if (memo.containsKey(index)) return memo.get(index);

    boolean isReachable = false;
    for (int i = 1; i <= nums.get(index); i++) {
        if (arrayStepper(index + i, nums, memo)) {
            isReachable = true;
            break;
        }
    }

    memo.put(index, isReachable);
    return isReachable;
}
```

> **Base-case ordering matters.** `index == size - 1` must be checked **before** the overshoot check, otherwise the destination itself gets rejected. The original had them as two separate `if`s in the right order — the collapsed form above says the same thing in one line, but either is fine. What is *not* fine is checking overshoot first.
>
> **Ask about the constraint in the interview:** the "may take *up to* `nums[i]` steps" wording is what makes overshoot possible and forces the two-case base. If steps were exact, this becomes a much simpler problem.
>
> **Worth mentioning:** the greedy `O(n)` solution (track the furthest reachable index in one pass) beats DP here. Naming it after you give the DP answer is a strong signal.

**Complexity:** `O(n × maxStep)` time, `O(n)` space.

# String problems

> Two distinct sub-families, and confusing them costs a lot of time:
>
> - **Two-pointer subsequences** (#10, #11) — state is a *pair* of positions, `O(n²)` states.
> - **Single-index segmentation** (#12–#15) — state is *one* position, `O(n)` states, and every one of them is `minChange` in disguise.

## 10. Max Palindromic Subsequence

**Problem**
- Return the length of the longest **subsequence** that is a palindrome.
- A subsequence deletes any characters but preserves relative order.
- `"luwxult" → 5`, `"lol" → 3`

**Skeleton**
- **State:** `(front, back)` — a window into the string
- **Meaning:** longest palindromic subsequence within `str[front..back]`
- **Base:** `front > back → 0` (empty); `front == back → 1` (single char)
- **Combine:**
  - chars match → `2 + f(front+1, back-1)`
  - else → `MAX(f(front+1, back), f(front, back-1))`

> **Why matching chars need no `MAX`.** If `str[front] == str[back]`, wrapping them around the best inner solution is *always* at least as good as discarding either. So the branch is unconditional — no comparison needed. That asymmetry between the two branches is the insight to state out loud.

<img width="520" alt="maxPalinSubsequence window recursion" src="https://github.com/user-attachments/assets/8a98bd0b-9136-4c01-b69d-b4361d07b236" />
<img width="520" alt="maxPalinSubsequence memo table" src="https://github.com/user-attachments/assets/9397da6c-6618-4450-9d29-b37de96ae4b1" />

```java
public static int maxPalinSubsequence(String str) {
    return maxPalinSubsequence(str, 0, str.length() - 1, new HashMap<>());
}

private static int maxPalinSubsequence(String str, int front, int back,
                                       Map<String, Integer> memo) {
    if (front > back) return 0;
    if (front == back) return 1;

    String key = front + "--" + back;
    if (memo.containsKey(key)) return memo.get(key);

    int res;
    if (str.charAt(front) == str.charAt(back)) {
        res = 2 + maxPalinSubsequence(str, front + 1, back - 1, memo);
    } else {
        res = Math.max(
            maxPalinSubsequence(str, front + 1, back, memo),
            maxPalinSubsequence(str, front, back - 1, memo)
        );
    }

    memo.put(key, res);
    return res;
}
```

**Complexity:** `O(n²)` time and space.

## 11. Overlap Subsequence (LCS)

**Problem**
- Return the length of the longest subsequence common to **two** strings.
- `("dogs", "daogt") → 3`
- This is textbook **Longest Common Subsequence** — name it as such in an interview.

**Skeleton**
- **State:** `(i, j)` — one pointer per string
- **Meaning:** LCS length of `str1[i..]` and `str2[j..]`
- **Base:** either pointer exhausted → `0`
- **Combine:**
  - chars match → `1 + f(i+1, j+1)` (advance both)
  - else → `MAX(f(i+1, j), f(i, j+1))` (drop one char from either)

<img width="520" alt="overlapSubsequence recursion" src="https://github.com/user-attachments/assets/6900a440-8dd4-4586-b151-1d7d75fe3a16" />
<img width="520" alt="overlapSubsequence complexity" src="https://github.com/user-attachments/assets/6b86e570-dfde-470c-a2f7-e5aa38e2c52b" />

```java
public static int overlapSubsequence(String str1, String str2) {
    return overlapSubsequence(str1, str2, 0, 0, new HashMap<>());
}

private static int overlapSubsequence(String str1, String str2, int s1, int s2,
                                      Map<String, Integer> memo) {
    if (s1 >= str1.length() || s2 >= str2.length()) return 0;

    String key = s1 + "--" + s2;
    if (memo.containsKey(key)) return memo.get(key);

    int res;
    if (str1.charAt(s1) == str2.charAt(s2)) {
        res = 1 + overlapSubsequence(str1, str2, s1 + 1, s2 + 1, memo);
    } else {
        res = Math.max(
            overlapSubsequence(str1, str2, s1 + 1, s2, memo),
            overlapSubsequence(str1, str2, s1, s2 + 1, memo)
        );
    }

    memo.put(key, res);
    return res;
}
```

> **Same shape as #10.** Palindromic subsequence *is* LCS of a string with its own reverse. Noticing that connection out loud is worth more than the code.

**Complexity:** `O(n × m)` time and space.

## 12. Can Concat

**Problem**
- Can the target string be built by concatenating words from the list?
- Words may be reused without limit.
- `("oneisnone", ["one","none","is"]) → true`
- `("oneisnone", ["on","e","is"]) → false`

**Skeleton**
- **State:** `i` — how far into the string we've consumed
- **Meaning:** can `s[i..]` be built?
- **Base:** `i == s.length() → true` (nothing left to build)
- **Combine:** `OR` over every word that prefixes `s` at `i`

<img width="520" alt="canConcat recursion tree" src="https://github.com/user-attachments/assets/73c0705e-e9de-488b-a3a9-cd63dae0d2ad" />
<img width="520" alt="canConcat complexity" src="https://github.com/user-attachments/assets/abbb46c3-d874-45c5-a3dc-a631cdecd708" />

```java
public static boolean canConcat(String s, List<String> words) {
    return canConcat(s, words, 0, new HashMap<>());
}

private static boolean canConcat(String s, List<String> words, int i,
                                 Map<Integer, Boolean> memo) {
    if (i == s.length()) return true;
    if (memo.containsKey(i)) return memo.get(i);

    for (String word : words) {
        if (s.startsWith(word, i) && canConcat(s, words, i + word.length(), memo)) {
            memo.put(i, true);
            return true;
        }
    }

    memo.put(i, false);
    return false;
}
```

> **`s.startsWith(word, i)` — memorise this overload.** The obvious `s.substring(i).startsWith(word)` allocates a fresh string on **every check inside a nested loop**, turning an `O(n × w)` algorithm into `O(n² × w)` on copying alone. The two-argument overload does the identical comparison at the offset with zero allocation. This single detail appears in #12, #13, #14 and #15.

**Complexity:** `O(n × w × L)` time (`w` words, `L` max word length), `O(n)` space.

## 13. Quickest Concat

**Problem**
- Return the **minimum number of words** needed to build the string by concatenation.
- Reuse allowed. Return `-1` if impossible.

**Skeleton**
- **State:** `i` — position in the string
- **Meaning:** fewest words to build `s[i..]`
- **Base:** `i == s.length() → 0`
- **Combine:** `MIN(1 + sub)` over matching words, skipping `sub < 0`

> **This is `minChange` with a different alphabet.** Amount → string position; coin → word; `amount - coin` → `i + word.length()`. If you can see that mapping, you already know the answer.

<img width="520" alt="quickestConcat recursion" src="https://github.com/user-attachments/assets/d395fca0-8396-494f-9644-0d38233474bd" />
<img width="520" alt="quickestConcat memo walkthrough" src="https://github.com/user-attachments/assets/641c15cd-b254-4683-bd78-e9a565be4543" />
<img width="280" alt="quickestConcat complexity" src="https://github.com/user-attachments/assets/378621f9-73e1-4256-908d-1296b72128c9" />

```java
public static int quickestConcat(String s, List<String> words) {
    return quickestConcat(s, words, 0, new HashMap<>());
}

private static int quickestConcat(String s, List<String> words, int i,
                                  Map<Integer, Integer> memo) {
    if (i == s.length()) return 0;
    if (memo.containsKey(i)) return memo.get(i);

    int shortest = Integer.MAX_VALUE;
    for (String word : words) {
        if (s.startsWith(word, i)) {
            int curr = quickestConcat(s, words, i + word.length(), memo);
            if (curr >= 0) {
                shortest = Math.min(shortest, 1 + curr);
            }
        }
    }

    int res = (shortest == Integer.MAX_VALUE) ? -1 : shortest;
    memo.put(i, res);
    return res;
}
```

> **Changed from the original:** it took the `MIN` of raw sub-answers and added `1` at the very end (`shortest + 1`). That is arithmetically equivalent — `min(a,b) + 1 == min(a+1, b+1)` — so it wasn't a bug. But it splits one idea across two places, and once you add a second `+1` anywhere (weighted words, for instance) the equivalence breaks silently. Putting `1 +` at the point of use keeps the recurrence readable as a single expression.
>
> Also switched `s.substring(i).startsWith(word)` → `s.startsWith(word, i)` (see #12).

**Complexity:** `O(n × w × L)` time, `O(n)` space.

## 14. Valid Compound

**Problem**
- Can the target compound be built by concatenating element symbols?
- Elements may be reused without limit.
- `validCompound("neco", ["Ne","O","Be","I","N","Os","Si","S","Co","C","Ir"]) → true`
  - `Ne + Co`, or `N + O + C + O`

**Skeleton**
- **State:** `c` — position in the compound
- **Meaning:** can `compound[c..]` be built?
- **Base:** `c == compound.length() → true`
- **Combine:** `OR` over every element matching at `c`

> **Identical to `canConcat`.** The only new wrinkle is casing — see the note below.

<img width="520" alt="validCompound recursion" src="https://github.com/user-attachments/assets/11694b7e-ed26-43e3-8b2d-d4cd77b96598" />
<img width="520" alt="validCompound memo walkthrough" src="https://github.com/user-attachments/assets/cb8db641-ac83-4f47-b8ae-a2346966b1e6" />

```java
public static boolean validCompound(String compound, List<String> elements) {
    return validCompound(compound, elements, 0, new HashMap<>());
}

private static boolean validCompound(String compound, List<String> elements, int c,
                                     Map<Integer, Boolean> memo) {
    if (c == compound.length()) return true;
    if (memo.containsKey(c)) return memo.get(c);

    boolean isValid = false;
    for (String element : elements) {
        if (matchesAt(compound, c, element)
                && validCompound(compound, elements, c + element.length(), memo)) {
            isValid = true;
            break;
        }
    }

    memo.put(c, isValid);
    return isValid;
}

/** Case-insensitive prefix test at an offset — no substring allocation. */
private static boolean matchesAt(String s, int offset, String prefix) {
    return s.regionMatches(true, offset, prefix, 0, prefix.length());
}
```

> **On the casing.** The inputs are genuinely mismatched: the compound arrives lowercase (`"neco"`) while element symbols are properly capitalised (`"Ne"`, `"Co"`). So normalising is **required**, not incidental — dropping it makes every match fail.
>
> The original did `element.toLowerCase()` inside the inner loop, which re-lowercases the same string on every position — quadratic-ish garbage generation. `String.regionMatches(true, …)` does a case-insensitive comparison at an offset with **no allocation at all**, replacing both `substring` and `toLowerCase` in one call. If you'd rather not reach for `regionMatches` under pressure, the pragmatic alternative is to lowercase the compound and every element **once, up front**, before recursing.
>
> Also changed `Integer c` → `int c`. Boxing a loop counter is pointless, and `Integer == Integer` compares references above the cache range (127) — a trap not worth leaving in your muscle memory.

**Complexity:** `O(n × e × L)` time, `O(n)` space.

## 15. Count Compounds

**Problem**
- Return the **number of distinct ways** to build the compound from element symbols.
- Reuse allowed.
- `countCompounds("neco", ["Ne","O","Be","I","N","Os","Si","S","Co","C","Ir"]) → 2`
  - `Ne + Co` and `N + O + C + O`

**Skeleton**
- **State:** `c` — position in the compound
- **Meaning:** number of ways to build `compound[c..]`
- **Base:** `c == compound.length() → 1` ⚠️
- **Combine:** `SUM` of all matching branches — **no `break`**

> ### The two things that flip when going from #14 to #15
>
> 1. **Base case becomes `1`, not `true`/`0`.** The empty suffix has exactly *one* way to be made: use nothing. If you write `0`, every path multiplies through zero and the answer is always `0`.
> 2. **No `break`, no truthiness test.** In #14 the first success ends the search. Here every branch contributes, so you must add the returned *count*, not `1`.
>
> The second point is the mistake that looks correct on small inputs:
> ```java
> // WRONG — counts which elements start a valid path
> if (matches && count(c + len) > 0) compoundCount += 1;
>
> // RIGHT — counts how many paths exist
> if (matches) compoundCount += count(c + len);
> ```
> **Counter-example:** `"aaa"` with `["a","aa"]`. True answer is `3` (`a+a+a`, `a+aa`, `aa+a`). The wrong version returns `2`, because at position `0` the suffix `"aa"` has two ways but gets recorded as one. The undercount compounds as the string grows — which is exactly why it passes short test cases.

<img width="520" alt="countCompounds recursion" src="https://github.com/user-attachments/assets/30e30a8b-5de3-41fe-9b02-49230934efbe" />
<img width="520" alt="countCompounds memo walkthrough" src="https://github.com/user-attachments/assets/3540022a-02a3-48e1-924f-2046092f652b" />
<img width="200" alt="countCompounds complexity" src="https://github.com/user-attachments/assets/d925b19b-0af0-47fb-bb8a-3b1a2420034e" />

```java
public static int countCompounds(String compound, List<String> elements) {
    return countCompounds(compound, elements, 0, new HashMap<>());
}

private static int countCompounds(String compound, List<String> elements, int c,
                                  Map<Integer, Integer> memo) {
    if (c == compound.length()) return 1;          // empty suffix: exactly one way
    if (memo.containsKey(c)) return memo.get(c);

    int compoundCount = 0;
    for (String element : elements) {
        if (matchesAt(compound, c, element)) {
            compoundCount += countCompounds(compound, elements,
                                            c + element.length(), memo);
        }
    }

    memo.put(c, compoundCount);
    return compoundCount;
}
```

*(Reuses `matchesAt` from #14.)*

**Complexity:** `O(n × e × L)` time, `O(n)` space.

# DAG problems

> These break the pattern: **memo *is* the answer table**, and you seed or iterate over every node because the path may start anywhere.

## 16. Longest Path

**Problem**
- Adjacency list for a **directed acyclic graph**.
- Return the length of the longest path, measured in **edges** (not nodes).
- A path may start and end at any two nodes.
- `{a: [c,b], b: [c], c: []} → 2` (`a → b → c`)

**Skeleton**
- **State:** `node`
- **Meaning:** longest path *starting at* this node, in edges
- **Base:** terminal node (no neighbours) → `0`, **seeded up front**
- **Combine:** `1 + MAX(distance of neighbours)`
- **Answer:** `max` over all nodes — not a single root

<img width="520" alt="longestPath DAG traversal" src="https://github.com/user-attachments/assets/35685e5a-3b6b-40db-b184-72f88f9bd1d3" />
<img width="200" alt="longestPath complexity" src="https://github.com/user-attachments/assets/0c5c4dbf-ee8d-4877-9828-4c515ef31b5d" />

```java
public static int longestPath(Map<String, List<String>> graph) {
    Map<String, Integer> distance = new HashMap<>();

    // seed terminal nodes with 0 — no outgoing edges means no path length
    for (String node : graph.keySet()) {
        if (graph.get(node).isEmpty()) {
            distance.put(node, 0);
        }
    }

    for (String node : graph.keySet()) {
        traverseDistance(node, graph, distance);
    }

    return Collections.max(distance.values());
}

private static int traverseDistance(String node, Map<String, List<String>> graph,
                                    Map<String, Integer> distance) {
    if (distance.containsKey(node)) return distance.get(node);

    int max = 0;
    for (String neighbor : graph.get(node)) {
        max = Math.max(max, traverseDistance(neighbor, graph, distance));
    }

    distance.put(node, max + 1);
    return max + 1;
}
```

> **Why terminals must be pre-seeded.** Without seeding, a terminal node would fall through to `distance.put(node, 0 + 1)` and be recorded as `1` — counting the node instead of an edge, inflating every answer by one. Compare this directly with #17, where **you want that off-by-one**.
>
> **Why the outer loop over all nodes.** Unlike a grid or a string, there's no fixed start. The longest path might begin at any node, so you must launch a traversal from each and take the global max. Memoization means the total work is still `O(V + E)`.
>
> **Why acyclicity matters.** The `distance.containsKey` check doubles as cycle protection only because the graph is a DAG. On a cyclic graph this recurses forever — if the interviewer removes the DAG guarantee, you need an explicit "in-progress" set.

**Complexity:** `O(V + E)` time, `O(V)` space.

## 17. Semesters Required

**Problem**
- `n` courses with ids `0 … n-1`, plus a list of prerequisite pairs.
- `[A, B]` means A must be taken in a **strictly earlier** semester than B.
- Unlimited courses per semester, as long as prerequisites are met.
- Return the minimum number of semesters. Assume it's always completable.
- `n = 6`, prereqs `[[1,2],[2,4],[3,5],[0,5]] → 3`

**Skeleton**
- **State:** `course`
- **Meaning:** semesters needed to finish this course **and everything downstream of it**
- **Base:** no dependents → `1` (falls out naturally, no seeding)
- **Combine:** `1 + MAX(distance of dependents)`
- **Answer:** `max` over all courses

> **The reframe:** this is #16 counting **nodes** instead of edges. The answer is the length of the longest prerequisite *chain*, because everything not in that chain can be taken in parallel alongside it. Absence of a limit on courses per semester is what makes "longest chain" the whole answer.

<img width="340" alt="semestersRequired prerequisite graph" src="https://github.com/user-attachments/assets/398d9147-1889-47bb-829b-e17dd46d1ed8" />
<img width="520" alt="semestersRequired traversal" src="https://github.com/user-attachments/assets/69643bec-bd32-49a0-9de4-471930c0bb74" />
<img width="160" alt="semestersRequired complexity" src="https://github.com/user-attachments/assets/0841215b-5c38-416e-962e-856b3270859b" />

```java
public static int semestersRequired(int numCourses, List<List<Integer>> prereqs) {
    Map<Integer, List<Integer>> graph = buildGraph(numCourses, prereqs);
    Map<Integer, Integer> distance = new HashMap<>();

    for (int node : graph.keySet()) {
        traverseDistance(node, graph, distance);
    }

    return Collections.max(distance.values());
}

private static int traverseDistance(int node, Map<Integer, List<Integer>> graph,
                                    Map<Integer, Integer> distance) {
    if (distance.containsKey(node)) return distance.get(node);

    int max = 0;
    for (int neighbor : graph.get(node)) {
        max = Math.max(max, traverseDistance(neighbor, graph, distance));
    }

    distance.put(node, max + 1);
    return max + 1;
}

private static Map<Integer, List<Integer>> buildGraph(int numCourses,
                                                      List<List<Integer>> prereqs) {
    Map<Integer, List<Integer>> graph = new HashMap<>();
    for (int node = 0; node < numCourses; node++) {
        graph.put(node, new ArrayList<>());   // isolated courses must still appear
    }
    for (List<Integer> prereq : prereqs) {
        graph.get(prereq.get(0)).add(prereq.get(1));   // A → B: A before B
    }
    return graph;
}
```

> **The one difference from #16, and it's deliberate.** No terminal seeding here. A course with no dependents falls through to `max + 1 = 1`, which is exactly right — that course still takes one semester. Counting nodes, not edges.
>
> **Don't skip `buildGraph`'s first loop.** Pre-populating all `n` ids with empty lists is what keeps a course that appears in no prerequisite pair from being missed — and prevents `graph.get(node)` returning `null` mid-traversal.
>
> **Edge direction is the classic slip.** `[A, B]` means "A before B", so the edge goes `A → B` and `distance[A]` must be larger. Draw two nodes and one arrow before you write the line.
>
> **Trace it (n=6):** node 4 → 1. Node 2 → 4, so 2. Node 1 → 2, so **3**. Node 5 → 1. Nodes 0 and 3 → 2 each. Max = **3**. ✅

**Complexity:** `O(V + E)` time, `O(V)` space.

# Appendix A: Bottom-up templates

Converting top-down to bottom-up is mechanical once you see the array as **one box per state, zero included**:

> An inclusive range `a..b` contains `b - a + 1` values. `0..amount` → `amount + 1` boxes.
>
> *A 12-inch ruler has 13 tick marks, because you have to mark the zero.*

**Direction rule:** walk so that the boxes you read are already filled. Numeric targets go **left to right** (`dp[i]` reads `dp[i - coin]`). String segmentation goes **right to left** (`dp[i]` reads `dp[i + len]`).

### Sum Possible — `OR`

```java
public static boolean sumPossible(int amount, int[] numbers) {
    boolean[] dp = new boolean[amount + 1];
    dp[0] = true;                                 // free answer, and the foothold

    for (int i = 1; i <= amount; i++) {
        for (int num : numbers) {
            if (i - num >= 0 && dp[i - num]) {
                dp[i] = true;
                break;                            // any path suffices
            }
        }
    }
    return dp[amount];
}
```

### Min Change — `MIN`

```java
public static int minChange(int amount, int[] coins) {
    int impossible = amount + 1;                  // > any real answer (all 1s = amount)
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, impossible);
    dp[0] = 0;

    for (int i = 1; i <= amount; i++) {
        for (int coin : coins) {
            if (i - coin >= 0 && dp[i - coin] + 1 < dp[i]) {
                dp[i] = dp[i - coin] + 1;         // no break — need the cheapest
            }
        }
    }
    return dp[amount] == impossible ? -1 : dp[amount];
}
```

> **Never `Integer.MAX_VALUE` as the sentinel in bottom-up.** Here you *do* compute `dp[i-coin] + 1` on unreachable boxes, and `MAX_VALUE + 1` wraps negative — it then wins every comparison and silently corrupts the whole table. `amount + 1` is provably larger than any legitimate answer and survives the `+ 1`.

### Count Compounds — `SUM`, right to left

```java
public static int countCompounds(String compound, List<String> elements) {
    int n = compound.length();
    int[] dp = new int[n + 1];
    dp[n] = 1;                                    // empty suffix: exactly one way

    for (int i = n - 1; i >= 0; i--) {
        for (String element : elements) {
            if (compound.regionMatches(true, i, element, 0, element.length())) {
                dp[i] += dp[i + element.length()];
            }
        }
    }
    return dp[0];
}
```

### Non-Adjacent Sum — `MAX`, `O(1)` space

```java
public static int nonAdjacentSum(List<Integer> nums) {
    int takePrev = 0, skipPrev = 0;               // dp[i+2], dp[i+1]

    for (int i = nums.size() - 1; i >= 0; i--) {
        int curr = Math.max(nums.get(i) + takePrev, skipPrev);
        takePrev = skipPrev;
        skipPrev = curr;
    }
    return skipPrev;
}
```

> **When to volunteer the rolling-array trick:** any recurrence that reaches back a *fixed* distance (`i+1`, `i+2`) needs only that many variables, not the whole array. Recurrences that reach back a *variable* distance (`i - coin`) need the full table.

# Appendix B: Bug checklist

Run this list mentally before saying "done". Every item bit at least one solution in these notes.

**Sentinels and base cases**
- [ ] Does the base case return the right **identity** for the verb? `true` / `1` / `0` / `0` — not whatever felt natural.
- [ ] Is the "impossible" sentinel **excluded from `MIN`/`MAX`**, via a `>= 0` guard or a value guaranteed to lose?
- [ ] Are you storing the sentinel in the memo and converting to `-1` only at the **boundary**? Never both styles at once.
- [ ] Is `Integer.MAX_VALUE` ever on the left of a `+`? *(#3, #5, Appendix A)*

**Off-by-one**
- [ ] Last valid index is `size() - 1`, never `size()`. *(#6 returned `0` for everything on this alone.)*
- [ ] `dp` array sized `amount + 1` / `n + 1` — largest index you touch, plus one.
- [ ] Is the destination base case checked **before** the overshoot check? *(#9)*

**Java specifics**
- [ ] `.equals()` for Strings, never `==`. *(#6 — works with literals, fails with runtime input.)*
- [ ] `s.startsWith(word, i)` instead of `s.substring(i).startsWith(word)`. *(#12–#15)*
- [ ] `int`, not `Integer`, for indices and counters. *(#14, #15)*
- [ ] Composite memo keys: `r + "--" + c`, never `r + c` — `(1,3)` and `(3,1)` collide, and so do `(2,2)` and `(1,3)`.

**Structure**
- [ ] Does every loop iteration **write** its result somewhere? *(Computing `min` and never assigning `dp[i]` is the easiest bug to stare past.)*
- [ ] Is the "did anything work?" decision **outside** the inner loop, where all options have been tried?
- [ ] `break` only on `OR` problems. Any `MIN`/`MAX`/`SUM` needs every branch. *(#15)*
- [ ] Do you accumulate the **returned count**, or just `+= 1`? *(#15 — the bug that passes small tests.)*
- [ ] Does `memo.put` run on **every** exit path, including the negative one?
- [ ] Is the memo shared across the whole recursion, not re-created inside it?

**State design**
- [ ] Does the state capture **everything** that changes the answer? *(#4 needs the coin index; without it you count permutations.)*
- [ ] Conversely — is any state dimension redundant? Extra dimensions cost real time and space.

| 17 | Semesters Required | MAX | `node` | `O(V + E)` | `O(V)` |

**The general rule:** `time = (number of states) × (work per state)`. Say the states out loud, then say the loop inside. That's the answer — no summing of series required.

## Pre-interview drill (5 minutes)

1. **Say the state and its meaning out loud.** If you can't finish *"`f(x)` returns …"*, you're not ready to write the loop.
2. **Name the verb.** OR / SUM / MIN / MAX. The base case and not-found value follow from it automatically.
3. **Draw and label the boxes** for a tiny input. The array size is however many labels you wrote — not a formula to recall.
4. **State the complexity as states × work.**
5. **Then** write code, and run Appendix B over it before saying "done".
